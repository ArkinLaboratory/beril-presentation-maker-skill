v0.3.8: process-detail-bleed post-checker (advisory only)

Mechanical scan over slide_spec content + speaker_notes for internal-
artifact references that consistently leak into shipped decks despite
slide_compose / revise_slide prompts. Surfaced by 2026-05-06
ibd_phage_targeting talk-45 review where a memoryless peer-scientist
flagged ~11 of 37 slides leaking patterns like:

  "REPORT.md §Pillar 2 opener #6; NB04h_hmp2_external_replication.ipynb"
  "L13 sensitivity analysis confirms"
  "data/nb05_tier_a_scored.tsv has the matrix"
  "OR=44.4 is an upper bound (L13); E. coli-specificity qualitatively
   robust across comparator choices. H3c interaction-term test not run"
  "Five-layer pipeline (NB01b → NB02 → NB04c-e → NB04h)"

These read as internal jargon to peer audiences. The check is
ADVISORY by design — the orchestrator never blocks on hits. It exists
to surface the failure class so authors hand-edit before shipping.

Files added

  src/beril_presentation_maker/skill/tools/check_no_artifact_refs.py
    Mirrors check_quantitative_grounding.py architecture. Six
    ArtifactPattern categories with tight regexes:
      - notebook-id          NB04, NB04b, NB04c-e, NB07 v1.8
      - notebook-file        NB04h_hmp2_external.ipynb
      - data-tsv-path        data/nb05.tsv, data/results.csv,
                             data/foo.parquet
      - report-md-section    REPORT.md, REPORT §16, REPORT.md §Pillar 2
      - pillar-section       §Pillar 2, §Pillar 3 (project-internal
                             organizing concept)
      - analysis-layer-code  L13, A16, H3c, E1, E3 (bracketed-style
                             abbreviations)

    Whitelists TL\d / S\d (throughline + substory IDs — legitimate
    project structure, NOT internal artifacts).

    Per-slide grouped output with location labels:
      bullets[2], caption, speaker_notes, image_prompt, etc.
    Each hit carries: slide_id, slide_position, slide_layout, location,
    pattern_name, matched_text, ±30-char context, explanation, fix
    suggestion.

    Writes:
      <draft_dir>/audit/no_artifact_refs.md   (human-readable)
      <draft_dir>/audit/no_artifact_refs.json (machine-readable)

    Exit codes:
      0  zero hits (clean) OR hits-but-advisory-mode (default)
      1  hits found AND --strict mode (orchestrator-callable for CI)
      2  runtime error (missing inputs, malformed JSON)

    Flag matrix: --strict, --quiet, --json-only.

  tests/unit/test_check_no_artifact_refs.py (NEW, 74 tests)
    - Pattern unit tests: each ArtifactPattern's regex against
      positive examples (real artifact-laden text) and negative
      examples (clean prose). Whitelist test confirms TL1/TL2/S1/S2
      are NOT flagged by the analysis-layer-code pattern.
    - Slide-text traversal: text fields, list fields, dict-list
      bullets (implications layout), speaker_notes.
    - scan_slide unit tests: clean slide returns no hits;
      artifact-laden slide produces 5+ hits across categories.
    - scan_slide_spec aggregator: empty / clean / mixed specs.
    - render_markdown: pass-message on clean reports; per-slide
      sections + advisory wording on dirty reports.
    - CLI: --strict / --quiet / --json-only / error paths
      (missing draft_dir / missing slide_spec / malformed JSON).
    - Real-data regression: against the actual ibd_phage_targeting
      slide_spec.json fixture, asserts ≥10 slides flagged + 4 specific
      pattern categories fire.

What's NOT in v0.3.8 (deferred)

    that would teach the writer to substitute artifact citations
    with peer-readable evidence at authoring time. These are
    taste-level prompt engineering deferred to v0.3.9 / v0.4.x to
    bound pre-event ship risk. The post-checker is the back-stop;
    the prompt is the prevention.
  - citation_pool stage validator that would flag any citation entry
    whose only source is a filename. Deferred to v0.4.x.

    regression in prior tests.
