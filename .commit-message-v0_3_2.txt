v0.3.2: data_table layout

Adds the 16th layout to the production vocabulary. data_table renders
ranked Top-N candidates, comparison matrices, or any small tabular
result with KBase-branded styling. Closes the add_slide.v1-flagged
gap that previously fell back to claim_evidence with bullets-as-rows
(capped at 3, losing the bottom of any top-N list).

New

- data_table in slide_spec.LAYOUTS (LAYOUTS now 16 entries).
  Schema: title + columns (2-6) + rows (1-12) + optional caption,
  footnote, data_source, highlight_rows. Validator caps are
  presentation-floor readability constraints; all cells must be
  strings (callers own precision).
- _fill_data_table handler in assemble_pptx.py with KBase-branded
  styling (header in #007DC3, alternating bands, #F78E1E for
  highlight_rows). Auto-sized row height adapts to row count.
- SPEC_TO_MASTER_LAYOUT aliasing: data_table reuses data_figure's
  master-layout. Handler removes body placeholder and renders its
  own table — avoids needing a source-.potx update for every new
  spec layout.
- JSON schema regenerated with data_table_content defs.
- add_slide.v1.md: removed "fall back to claim_evidence" workaround
  for top-N data shapes; references v0.3.2 data_table directly.

Changed

- example_slide_spec() now produces 16 slides (was 15).
- LAYOUTS count: 15 → 16.

Tests

- 12 new schema tests in test_slide_spec.py.
- test_assemble_pptx: existing tests updated for 16 slides + the
  data_table → data_figure master-layout aliasing.
- 483/483 unit tests pass (was 471 in v0.3.1).

Out of v0.3.2 scope

- Per-column width hints. Equal-fraction widths render acceptably
  for 2-6 cols.
- Data-driven cell highlighting. highlight_rows is sufficient for
  top-N emphasis.

Verification

- Wheel rebuilds clean.
