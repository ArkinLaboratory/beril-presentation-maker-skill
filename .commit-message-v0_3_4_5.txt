v0.3.4.5: configure-command hotfix — adversarial CLI name + CBORG_API_KEY check

Two real bugs surfaced by Adam's first hub install dry-run on the
KBERDL JupyterHub 2026-05-04. Configure command worked structurally
but reported wrong information:

Bug 1 — Adversarial CLI binary name mismatch

`commands/configure.py` checked `shutil.which("beril-adversarial-cli")`
to detect the adversarial CLI installation. That binary never
existed: adversarial's CLI binary is `beril-adversarial` (no `-cli`
suffix; subcommands are `install-skill` / `configure` / `review`).
Result: configure always reported `[absent]  beril-adversarial` even
when adversarial v0.7.0.1 was installed and on PATH.

Same wrapper-naming gap memorialized in
`feedback_verify_cli_before_recommending.md` 2026-05-02: I told Adam
to run nonexistent `beril-adversarial-cli` invocations twice. This
configure check was the third instance.

Fix:
- Change `shutil.which("beril-adversarial-cli")` →
  `shutil.which("beril-adversarial")`.
- When found, also probe `beril-adversarial --help` for the v0.6.0+
  `review` subcommand and report version + maturity marker. v0.3.3.1+
  presentation-maker requires v0.6.0+ for the consumer-side migration
  (central_objection rename + citation_reality routing); the configure
  output now surfaces that requirement explicitly.
- Updated install hint URL: was the SSH-only form, now uses HTTPS
  with @v0.7.0.1 tag pin (matches HUB_INSTALL.md operator runbook).

Bug 2 — CBORG_API_KEY check missing entirely

HUB_INSTALL.md L97-100 documented that configure reports CBORG_API_KEY
status (set / not set in env / readable from BERIL_ROOT/.env). The
actual code didn't have that check. Docs-vs-code drift — the
documented behavior was aspirational.

Fix:
- New `_resolve_cborg_api_key_status(beril_root)` helper. Mirrors the
  orchestrator's resolution order:
    1. Shell env `$CBORG_API_KEY`
    2. `BERIL_ROOT/.env` line `CBORG_API_KEY=...` (handles quoted
       values, blank lines, comments; treats empty RHS as unset).
    3. None — image_gen will skip with a clear stderr.
- Returns `{"found": bool, "source": str}`. The "source" field
  describes WHERE the key was found, not WHAT was found —
  CRITICAL invariant per `feedback_secret_file_handling.md`.
- New configure section between bash-version and informational
  sections that surfaces the resolution status. When found,
  reports the source. When absent, prints the exact `echo
  CBORG_API_KEY=... >> $BERIL_ROOT/.env` recipe to fix.
