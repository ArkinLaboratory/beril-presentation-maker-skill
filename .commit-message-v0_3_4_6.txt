v0.3.4.6: draft CLI auto-detects BERIL_ROOT via discovery walk-up

Hub-install ergonomic bug surfaced 2026-05-04 immediately after
v0.3.4.5 shipped. Adam ran on the KBERDL JupyterHub:

  BERIL_ROOT=~/BERIL-research-observatory
  beril-presentation-maker draft gene_function_ecological_agora ...
  → Error: --beril-root or $BERIL_ROOT must be set

Root cause: shell `BERIL_ROOT=path` (no `export`) sets a shell
variable but does NOT export it to subprocesses. Python's
subprocess.run inherits the parent process's exported env only.
The bash orchestrator's BERIL_ROOT validation hard-fails.

Hub users will routinely hit this. The fix is to make `draft`
auto-detect like `configure` already does:

- discovery.find_beril_root() walks up from cwd looking for a
  directory with .env + .claude/skills/ + at least one BERIL-core
  marker skill (submit / berdl / suggest-research). Same logic
  paper-writer and adversarial use.
- Adam was inside `<BERIL_ROOT>/projects/gene_function_ecological_agora/`
  when he invoked draft. Walk-up from there hits BERIL_ROOT in two
  parent steps. Auto-detect would have resolved cleanly.

Changes

1. `commands/draft.py::run()`:
   - Import the discovery module.
   - When `args.beril_root` is empty, call
     `discovery.find_beril_root()` to resolve via env-var or
     walk-up. Forward the resolved path to the bash subprocess as
     `--beril-root <resolved>`.
   - When discovery fails (BerilRootNotFound), exit 1 with a
     clear error message + actionable hint:
       cd into BERIL checkout, OR pass --beril-root <path>, OR
       `export BERIL_ROOT=<path>`.
   - Explicit `--beril-root` still wins over auto-detection (test
     pins this).

2. assemble.py: pure Python, no orchestrator subprocess. No fix
   needed.

3. continue_run.py: already had auto-derive in v0.3.4 — uses
   `draft_dir.parents[3]` (the path layout always implies BERIL_ROOT
   when draft_dir is a real talks/draft_N/ directory). Different
   mechanism, but works for the resume use case. No fix needed.

Tests

5 new unit tests in `tests/unit/test_draft.py` (NEW file):

- test_run_auto_detects_beril_root_when_not_passed: cwd inside a
  fake BERIL root → walk-up resolves → forwarded to subprocess.
- test_run_explicit_beril_root_overrides_detection: explicit
  --beril-root wins even when cwd-walkup would resolve elsewhere.
- test_run_uses_env_var_when_set: BERIL_ROOT exported in env →
  discovery uses env path even when cwd is unrelated.
- test_run_returns_1_with_clear_error_when_discovery_fails: no env
  var + no markers in cwd walk-up → rc=1 with hint about
  cd / --beril-root / export.
- test_run_validates_explicit_beril_root_via_discovery: explicit
  path NOT validated by discovery (forwards as-is to bash; bash
  validates). Pins this design choice — operators with non-standard
  layouts shouldn't be over-constrained by the wrapper.

Tests: 738 → 743 passed (5 new). 1 marker-gated live integration
test still skipped in sandbox.
