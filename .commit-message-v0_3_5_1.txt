v0.3.5.1: bash strict-mode patch in should_run() resume logic

Hub smoke run on ibd_phage_targeting (KBERDL JupyterHub, evening
2026-05-05) surfaced two bugs in succession during a Claude Code
agent's first end-to-end attempt at presentation drafting:

  (A) gate_throughline_pick blocks on `read -r pick </dev/tty`,
      which fails in TTY-less contexts (Claude Code background
      Bash tool, CI, headless daemon). Architectural — the
      synchronous-blocking-on-TTY interactivity model assumes the
      bash orchestrator owns a controlling terminal, which is wrong
      for hub agents and CI runs. Workaround for May 7: pass
      `--auto-advance` to skip the prompt (auto-picks TL1). Real
      fix (state-driven continue with explicit --pick TLN gate-
      resume, paper-writer pattern) tracked for v0.4.0; not safe
      to land in 36 hours pre-event.

  (B) should_run() declares `local order_resume order_stage`
      without initialization. Under bash 5.2 `set -u`, the
      `[[ -z "$order_resume" ]]` check after the case loop trips
      "unbound variable" if neither case-arm matched any iteration.
      Hidden until now because most prior tests run without
      --resume-from (which short-circuits before the loop). Hub
      agent hit it on first `continue --resume-from throughline`
      after working around bug A.

THIS COMMIT FIXES (B) ONLY.

Bug B fix

  src/beril_presentation_maker/skill/tools/presentation_maker.sh
  line 1740:

    -  local order_resume order_stage
    +  local order_resume="" order_stage=""

  Initializing to empty string (rather than declaring unset)
  satisfies `set -u` and matches the canonical bash pattern. Inline
  comment block added documenting the live-failure root cause for
  future readers.

Bug A workaround

  TUTORIAL.md §"Presentation-maker-specific troubleshooting" gets a
  dedicated entry as the first item explaining when `--auto-advance`
  is required (TTY-less contexts), with a forward pointer to v0.4.0
  for the architectural fix.

  docs/cross-skill/PARTICIPANT-RUNBOOK.md §Appendix A gets the same
  entry as the first failure mode listed (since it's the most likely
  to bite event participants running through Claude Code).

  Both docs are explicit that paper-writer is unaffected — its
  continue command already takes `--pick TLN` and does not depend
  on TTY for the throughline pick. This is the cross-skill
  consistency gap that should drive v0.4.0's design.

What's NOT in this commit

  - No state.json schema design.
  - No bash gate refactor to write state and exit cleanly.
  - No `continue --pick TLN` argparse extension.
  - No tests for the strict-mode case (it's a one-line init that
    any future `continue --resume-from <stage>` invocation re-
    validates; the live hub run is the regression evidence).

  All of the above lands in v0.4.0 post-event.

Tests

  Full suite passes: 746 unit tests, 1 marker-gated live integration
  test still skipped in sandbox. No new tests; no behavior change
  for code paths that were already working.
