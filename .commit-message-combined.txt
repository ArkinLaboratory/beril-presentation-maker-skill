v0.3.7: image_gen_decision LLM-judgment layer (kills "deferred to v0.3.4" bug)

Closes the long-standing "deferred to v0.3.4 LLM-judgment layer"
placeholder in image_gen_decision.py that was returning emit=false
for 6 layouts and silently producing zero AI illustrations on
figure-rich projects. Surfaced as a deck-level weakness during the
2026-05-06 memoryless-reviewer assessment of ibd_phage_targeting
talk-45: 0 AI illustrations in a 37-slide deck on a complex
biological topic that would have benefited from conceptual visuals
(mechanism cartoons, cocktail-strategy schematics, framework
diagrams).

What v0.3.7 ships

  src/beril_presentation_maker/skill/tools/image_gen_decision.py
    NEW llm_judge() function — synchronous claude -p call per
    deferred-layout slide. Per-slide prompt asks: "would a
    conceptual AI illustration add value beyond what this layout's
    existing content provides?" Returns (emit, reason) tuple.
    Defensive fallbacks: claude-not-on-PATH, subprocess timeout,
    non-zero exit, unparseable response — all return (False,
    descriptive_reason) without raising.

    NEW JudgeFn type alias (Callable[[dict, str, str], tuple[bool, str]]).
    Tests pass stub callbacks to avoid live LLM calls.

    decide() / decide_fragment() / emit_decisions() take new
    `judge_fn: Optional[JudgeFn]` parameter. When None (default),
    deferred layouts return emit=false with reason "needs LLM
    judgment but no judge_fn was provided" — preserves pre-v0.3.7
    conservative behavior for non-CLI callers and existing tests
    that don't pass judge_fn.

    NEW _build_judge_prompt() — discriminating prompt with explicit
    YES/NO criteria. YES for concept slides (mechanism, framework,
    abstraction, opening pivots); NO for data-heavy / structural /
    too-specific. When uncertain, prefer NO (illustrations cost
    ~$0.014 each and over-illustration distracts).

    NEW _parse_judge_response() — pure parser, strict on YES/NO
    prefix, permissive on separator (": ", "—", " - ", whitespace).
    Falls back to (False, reason) on unparseable responses.

    CLI _cmd_emit_decisions: auto-enables llm_judge when claude is
    on PATH. NEW --no-llm-judge flag for explicit opt-out (for
    tests, sandbox runs, or operators wanting pre-v0.3.7
    conservative behavior). NEW --judge-model flag (default
    claude-sonnet-4-6).

    Envelope: NEW llm_judgment_used boolean field on the
    image-decisions.v1 JSON envelope, allowing downstream consumers
    (or audit-log readers) to distinguish runs that used LLM
    judgment from runs that didn't.

  src/beril_presentation_maker/skill/tools/presentation_maker.sh
    Comment block in stage_image_gen updated to reflect the new
    behavior (auto-enabled when claude is on PATH; falls back to
    no-AI-image when absent). No flag-surface change at the
    orchestrator level — `--no-images` still skips the whole stage
    if users want that.

  tests/unit/test_image_gen_decision.py
    25 new unit tests in three classes:
      TestJudgeFnIntegration (5): judge_fn yes/no/exception paths,
        all 6 deferred layouts invoke it, non-deferred layouts skip it
      TestLLMJudgeHelper (6): claude-not-on-PATH fallback, parses
        YES/NO response, unparseable fallback, timeout fallback,
        non-zero exit fallback
      TestParseJudgeResponse (10): YES/NO parser edge cases —
        separators, missing reason, empty input, unparseable, multiline,
        case-insensitivity, surfaces head-of-response in unparseable case
      TestEmitDecisionsLLMJudgmentFlag (2): envelope flag false/true
        toggles correctly
      TestCLIWithLLMJudgeFlags (2): --no-llm-judge disables;
        claude-not-on-PATH falls back gracefully

    Existing test test_rule_5_deferred_layouts_skipped updated to
    match new "no judge_fn" reason text instead of "v0.3.4".

Cost analysis

  Per-slide LLM call: ~$0.005-0.01 on Sonnet 4.6 (~300 token prompt,
  ~30 token response).
  Per-draft cost overhead: $0.10-0.20 for typical 15-20 deferred
  slides.
  Per-image generation cost (downstream, unchanged): ~$0.014/image
  via CBORG-Gemini.
  Total cost delta on a typical talk-30 STRONG: +$0.10-0.30
  judgment + $0.10-0.30 generation = +$0.20-0.60. Well within the
  $5-20/draft budget.

Latency

  Per-call: 2-5s typical, 60s timeout.
  Per-draft: +30-90s for 15-20 sequential calls. Acceptable; full
  pipeline is 60-120 min on the hub. Parallelization deferred to
  v0.4.0+.

v0.3.8: process-detail-bleed post-checker (advisory only)

Mechanical scan over slide_spec content + speaker_notes for internal-
artifact references that consistently leak into shipped decks despite
slide_compose / revise_slide prompts. Surfaced by 2026-05-06
ibd_phage_targeting talk-45 review where a memoryless peer-scientist
flagged ~11 of 37 slides leaking patterns like:

  "REPORT.md §Pillar 2 opener #6; NB04h_hmp2_external_replication.ipynb"
  "L13 sensitivity analysis confirms"
  "data/nb05_tier_a_scored.tsv has the matrix"
  "OR=44.4 is an upper bound (L13); E. coli-specificity qualitatively
   robust across comparator choices. H3c interaction-term test not run"
  "Five-layer pipeline (NB01b → NB02 → NB04c-e → NB04h)"

These read as internal jargon to peer audiences. The check is
ADVISORY by design — the orchestrator never blocks on hits. It exists
to surface the failure class so authors hand-edit before shipping.
