v0.3.5: data_figure caption overflow — 3-layer fix

First post-hub-install live deck (gene_function_ecological_agora,
draft_1, 30 slides, $16.14, generated 2026-05-04) surfaced two
slides with the same visual failure:

  - slide 21 (top-N comparison): ~410-char caption
  - slide 23 (selection-signature): ~380-char caption

Both captions wrapped past their 0.65-in textbox at y=4.18..4.83 and
rendered text into the y=5.00 KBase brand strip (DOE / KBase / LBNL
logos), producing a "garbled cartouche" effect on every projected
display.

Root-cause walk

The v0.3.2.8 mitigation comment in `_fill_data_figure` claimed:

  # auto_size=False is critical: it prevents the caption box from
  # growing downward and overlapping the data_source band when the
  # caption is long.

This was a no-op. python-pptx's `add_textbox` writes
`<a:spAutoFit/>` by default, which corresponds to
`MSO_AUTO_SIZE.SHAPE_TO_FIT_TEXT` — the box GROWS to fit text. Our
wrapper's `auto_size=False` parameter just skipped the explicit
assignment, so the library default (grow-to-fit) still applied. The
bug had been latent since v0.3.2.8; the only reason draft_2 didn't
trip it was that revise-loop captions there happened to be
shorter. (Test
`tests/unit/test_assemble_pptx.py::test_add_textbox_shrink_to_fit_unit`
now pins this surprising python-pptx default.)

Three-layer fix

Per memory `feedback_prompt_tool_contract_drift.md`: prompt-only
caps drift; pin in code. Per `feedback_no_benchmark_gaming.md`:
diagnose before patching, fail loud.

  Layer 1 — Prompts (the LLM-side cap):
    - `prompts/slide_compose.v1.md`: data_figure authoring rule
      extends with "Hard caption length limit: 280 characters
      (250-char target)" + cite to live failure.
    - `prompts/revise_slide.v1.md`: NEW
      `### data_figure caption-length cap` section before
      `### claim_evidence`, with worked example of moving citations
      to `data_source`, dropping redundant phrasing, and surfacing
      in `revision_log`.

  Layer 2 — Validator (the contract-side cap):
    - `tools/slide_spec.py`: NEW `DATA_FIGURE_CAPTION_MAX_CHARS = 280`
      module-level constant. `_check_data_figure` now hard-fails any
      caption > cap. `assemble.py` runs the validator pre-render, so
      any spec produced by a future revise-loop run that exceeds
      280 chars is rejected before any .pptx is touched — the loop
      must re-emit shorter or escalate.

  Layer 3 — Render (belt-and-suspenders for any spec that bypasses
  the validator):
    - `tools/assemble_pptx.py`: `_add_textbox` extended with new
      `shrink_to_fit: bool = False` keyword arg. When True, sets
      `tf.auto_size = MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE` so the FONT
      shrinks to keep text inside the fixed-size box.
      `shrink_to_fit` is mutually exclusive with `auto_size` and
      wins when both are passed (documented in docstring + pinned
      by test).
    - `_fill_data_figure` now passes `shrink_to_fit=True` on the
      caption textbox call.

Why three layers, not just two

Catching the failure at the prompt level is unreliable (LLMs drift,
we've now seen this twice — v0.3.2.8 with 410 chars, v0.3.5 with
the same magnitude). Catching it at the validator level gives a
loud reject, but a manual edit of slide_spec.json or a future
validator regression would still let it through. The render-side
shrink-to-fit is the third layer that costs nothing on a properly-
sized caption (font scale stays at 100%) but bounds the worst case
when the other two layers fail.

Tests

6 new unit tests, 743 → 746 passed:

  validator (tests/unit/test_slide_spec.py):
    - test_data_figure_caption_at_cap_passes: caption == cap → ok.
      Also asserts the cap constant equals 280, so a rename or
      bump trips this test as a "did you also update the prompts?"
      reminder.
    - test_data_figure_caption_over_cap_rejected: caption == cap+1
      → validator emits message containing actual length, cap, and
      brand-strip / y=5.00 hint for the LLM.
    - test_data_figure_caption_410_char_live_failure_rejected:
      pin the magnitude of the live failure with a fixture that
      reproduces the gene_function_ecological_agora draft_1 slide-21
      caption shape. Future cap loosening trips this.

  render (tests/unit/test_assemble_pptx.py):
    - test_data_figure_caption_textbox_shrink_to_fit
      (@requires_master): the caption box at y≈4.18in has
      auto_size = TEXT_TO_FIT_SHAPE in the rendered .pptx.
    - test_add_textbox_shrink_to_fit_unit: unit-level pin on the
      kwarg → MSO_AUTO_SIZE mapping. Pins python-pptx's default
      (SHAPE_TO_FIT_TEXT) for unset textboxes — the surprising
      default that hid this bug for 2 versions.
    - test_add_textbox_shrink_to_fit_wins_over_auto_size: when
      both kwargs are True, shrink_to_fit takes precedence (matches
      the docstring contract).
