v0.3.3: image-gen orchestrator stage (Channel A end-to-end)

Closes the loop on the AI image-generation pipeline. The calibrated
client + ai_image_prompt.v1 prompt have been on-disk since v0.3.0;
this release wires them into the orchestrator so concept_illustration
slides actually receive AI-generated images during a normal run.

Authoritative design: V0_3_3_ARCHITECTURE.md.

Architecture summary

Two-layer pipeline (the punch-list's three-layer plan was collapsed
to two on Adam's review: the brief layer is the prompt's input, not
a separate LLM call). Inserted between speaker_notes and merge:

  1. Decision layer (Python, deterministic):
     - 16-layout closed-set partition; concept_illustration is the
       only YES; data_figure / data_table / structural slides are NO;
       claim_evidence / workflow_diagram / etc. deferred to v0.3.4
       LLM-judgment.
     - EXPLORATORY tier requires --image-allow-exploratory opt-in
       (architecture R6).
     - Already-resolved image_path (resume mode, cached fragment) →
       skip re-generation.
     - tools/image_gen_decision.py + 30 unit tests.

  2. Prompt+request layer (LLM, existing ai_image_prompt.v1.md
     unchanged): one Claude call per emit=true slide; emits
     working/05_image_requests/<slide_id>_request.json.

Per-slide pipeline

  decide → snapshot fragment → ai_image_prompt.v1 → verify
  slide_id_target → user approval gate → image_client.py generate →
  manifest entry + fragment mutation.

Approval gate (image_gen_approval.py): per-slide [a]/[r]/[v]/[A]/[R]/[q]
choices reading /dev/tty. The [e]dit choice is OMITTED in v0.3.3 (per
Adam 2026-05-03); power users hand-edit request.json between runs via
--resume-from image_gen instead.

Bulk-mode short-circuits via [A]/[R]; --auto-approve-images bypasses
the gate entirely for CI / power-user runs.

Cost capping

--max-image-cost-usd (default $0.50, ~30 images at $0.014 each on
gemini-3-pro-image). Worst-case-per-image preflight in image_client.py
+ cumulative cap enforced via manifest.total_cost_usd(). Budget
exhaustion → record-skipped (Option A applies; merge drops slide).

Slide-drop on rejection (architecture R6)

Rejected concept_illustration → manifest.add_rejected → merge drops
the slide entirely. The placeholder provenance ({approved_at: "TBD"})
would otherwise fail the spec validator's ISO-8601 check; dropping is
cleaner than relaxing the validator. Pre-image-gen fragment snapshot
preserved at audit/snapshots/03_slides_pre_image_gen/ for recovery.

Slide-id convention frozen across all v0.3.3 modules:
  S{N}-pos{P}     — substory slides (substory_id + 0-indexed position)
  intro-pos{P}    — intro slides

New modules (~1,845 LOC, 140 tests)

  tools/image_gen_decision.py        — Tier 1: decision layer + list-yes CLI
  tools/draft_paths.py (extension)   — Tier 2: 3 new path properties + snapshot subdir
  tools/image_gen_manifest.py        — Tier 3: image-manifest.v1 schema + writer
  tools/merge_compose_fragments.py   — Tier 4: --image-manifest-path arg, binding,
                                       slide-drop. Backwards-compat: absent
                                       manifest → no-op.
  tools/image_gen_approval.py        — Tier 5: per-slide gate + slide_id_target
                                       trust-but-verify
  tools/image_gen_orchestrate.py     — Tier 6a: Python helpers wrapping manifest
                                       + budget + fragment-mutation
  tools/presentation_maker.sh        — Tier 6b: stage_image_gen + 5 new flags
                                       + should_run ordinals + --resume-from
                                       image_gen + --image-manifest-path on
                                       merge invocation
  V0_3_3_ARCHITECTURE.md             — design baseline (361 lines)

Test counts: 525 (pre-v0.3.3) + 140 = 665 → 638 reported (some
parameterized expansions consolidate). All green.

CLI surface additions

Bash orchestrator (presentation_maker.sh):

  --no-images                  Skip image_gen stage entirely
  --auto-approve-images        Bypass per-slide approval gate
  --image-allow-exploratory    Allow concept_illustration on EXPLORATORY tier
  --max-image-cost-usd <n>     Cumulative cap (default 0.50)
  --image-style <style>        Optional style override (forwarded to
                               ai_image_prompt as STYLE_HINT)
  --resume-from image_gen      Re-run image generation only (uses
                               pre-image-gen snapshot for clean re-roll)

Python CLI wrappers (commands/draft.py + commands/continue_run.py):

The Python `beril-presentation-maker draft` and `continue` subcommands
have been extended to forward every v0.3.0 + v0.3.3 orchestrator flag.
Pre-v0.3.3, the wrappers only forwarded the v0.2.x flags
(--mode, --tier, --audience, --auto-advance, --skip-assembly, --model,
--no-stream); --no-adversarial, --max-revise-cost-usd, --max-revisions
(v0.3.0) and the 5 v0.3.3 image-gen flags were unreachable through the
wrapper. Smoke-detected gap during the v0.3.3 first-run; closed in
this commit. continue_run.py also adds 'image_gen' to its
_VALID_STAGES tuple for the new --resume-from value.

Backwards compatibility

Pre-v0.3.3 drafts: merge_compose_fragments treats absent manifest as
no-op (legacy v0.3.2 binding behavior preserved). --no-images runs
behave identically to v0.3.2. Existing 525 tests all still pass with
no modification.

Out of v0.3.3 scope

  - Channel B (user-initiated images via revise_loop or interactive
    command) — v0.4.x.
  - LLM-judgment "supplemental image needed?" decision on
    claim_evidence slides — v0.3.4 if smoke shows the deterministic
    gate misses real cases.
  - Vision-LLM quant-content judge integration — v0.4 (currently a
    stub in image_client.py; user-approval gate is load-bearing).
  - Direct-provider routing (Google AI Studio / OpenAI direct) — v0.4+.
  - "Re-roll on rejection" with corrective hint sub-loop — v0.4+.

Late-arrival fixes during 2026-05-03 ship-validation smoke

The first-run smoke surfaced five real bugs that all landed in this
v0.3.3 commit; documenting each so the post-mortem is searchable:

  1. usage() sed range silently truncated help mid-flag-block.
     Fixed by switching to awk-with-sentinel:
     `awk '/^set -euo pipefail/{exit} NR>=4{print}'`. Memorialized in
     memory feedback_help_text_no_magic_line_numbers.md so this
     class of bug doesn't recur.

  2. Python CLI wrappers (commands/draft.py + commands/continue_run.py)
     missing pass-through for v0.3.0 + v0.3.3 orchestrator flags.
     Both wrappers extended to forward --no-adversarial,
     --max-revise-cost-usd, --max-revisions, --no-images,
     --auto-approve-images, --image-allow-exploratory,
     --max-image-cost-usd, --image-style. continue_run.py also
     gains --beril-root with auto-derive from draft_dir.parents[3]
     (since the orchestrator requires BERIL_ROOT even in resume mode).
     continue_run._VALID_STAGES adds 'image_gen'.

  3. stage_merge_and_assemble: empty manifest_arg array crashed
     under `set -u`. Fixed with the canonical
     `${manifest_arg[@]+"${manifest_arg[@]}"}` expansion that's
     safe for empty arrays.

  4. CBORG_API_KEY auto-load. The orchestrator now reads
     BERIL_ROOT/.env on startup (mirrors image_gen_calibration.py
     precedence) so users don't have to manually `source` env.
     Never echoes the value. Inline Python extractor avoids
     leaking other vars from a `source` call.

  5. CONCEPT_STYLES contract drift. v0.3.0 calibration added 4
     new image styles to ai_image_prompt.v1.md (scientific_illustration
     as T2-winning default + watercolor / minimalist / abstract as
     alts) but slide_spec.py::CONCEPT_STYLES tuple never updated.
     Validator hard-rejected the calibrated default mid-pipeline
     after the API call had spent real money. Fixed by broadening
     CONCEPT_STYLES + regenerating slide_spec.schema.json + adding
     test_concept_styles_match_ai_image_prompt + test_concept_illustration_accepts_scientific_illustration
     contract pins. Memorialized as "fourth strike" in
     feedback_cross_skill_contract_drift.md (this one intra-skill
     not inter-skill, but identical pattern).

Live smoke validated end-to-end gen path on
core_gene_tradeoffs/draft_3 with a forced concept_illustration
slide: image generated successfully (729KB PNG, $0.014 actual cost,
$0.05 worst-case preflight bound), bound through manifest, embedded
in deck. Two polish observations tracked separately as backlog:
concept_illustration layout sizing (region is 1.22:1 but prompt
default is 16:9 → letterbox), and slide_compose layout-selection
bias against concept_illustration (0/22 emit on natural pipeline run
suggests the prompt under-uses this layout). Both ride in v0.3.x
backlog, not v0.3.3.

Total ship-validation spend: ~$5.99 across full pipeline + 2 failed
image-gen attempts (LLM authoring × 2) + successful image gen.
